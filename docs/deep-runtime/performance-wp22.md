# WP-22 同机 KVM 性能记录

2026-11-25，在 AMD Ryzen 7 8845H 上的嵌套 KVM Worker 测量。Worker 可用 6 个 vCPU，宿主内核 6.8.0-151-generic，实验目录位于本地 ext4。每台 OCI Guest 使用 2 vCPU、512 MiB、一块只读根盘和两块可写盘。测试在私有 mount 和网络命名空间运行，Guest 无 TAP。保留宿主页缓存。环境有同机后台活动。

基线 Bundle `sha256:3b1be2e1518a8a2027662e2fe79cd6a318e1d2b483cc5ef42e8f0b1d5594c22c`。干净负载预触碰相同的内存范围。写脏负载每个约 20 ms 心跳写一次 16 MiB 范围内的每一页。Guest 在两块可写盘上以 `fsync` 记录并校验连续计数。每个新身份的首任务由四个进程完成共 1,024 次直接随机读，校验 4 MiB 读结果，随后确认两盘计数连续。两轮按相同的 Guest 二进制执行；原始样本见 `.build/wp22/baseline-paired.json`。

每行是 p50 / p95。每个负载和场景有两次操作。双分支的首任务有四个目标样本。p95 使用最近秩，因此在此样本量下等于最大观测值。Worker 完成取操作回执首次达到终态的时间。源心跳空档取捕获期间 Guest 普通循环的最长间隔。首任务是提交到宿主观测到 Guest 报告结果的时间上界。

## 冻结安装的源 vCPU 停顿

2026-11-26，使用冻结安装 `fb69434`（Bundle `sha256:a9b41917173a0eea2306aa41276b59fa314e1d54f9d52f45766bcf2ce7698c35`）和以上两种 Guest 工作负载，完成 16 次受管 Fork。临时目录在 tmpfs，Guest 保持两块可写盘，宿主保留页缓存并有后台编译活动。每次捕获由 Worker 查询原 VMM 并取得 `HELD`。Linux perf 只记录该源 VMM 的两个 vCPU 线程，使用宿主 `CLOCK_MONOTONIC`、`kvm_exit` 和 `kvm_entry`。每条线程均取得查询之前的最后一次退出与查询之后的首次进入，两条线程的公共停顿从较晚的退出算到较早的再次进入。其间包含 vCPU 已退出 Guest 模式后的设备处理和宿主调度时间。

## 读盘通道对照

保留 16 条默认通道。可通过 `KRUN_BLOCK_READ_LANES` 选择更低的线程预算。本地双分支随机读中，减少通道降低了每台 VMM 的线程和 PSS。0 条时，批次完成 p95 升至 14.05 s，各配置首任务分布接近。网络盘、较大并发和编译吞吐仍待对照。

现有批次用一次捕获提供双分支相同的起始点。两轮观察到约 4.10–4.62 s 的源心跳空档，并在约 10.55–11.28 s 观测到源释放。优先进一步分解 Guest 冻结、writer pivot 和源返回各阶段的等待成本。dirty 增量优化继续等待 vCPU 与软件写并集的正确性及耗时对照。

保留现有 rebase 及耐久读取路径。递归验证通过，尚未测量等价 metadata 跳过 rebase 的收益。干净持久恢复的首次与重复首任务 p50 分别为 2.08 s 和 2.29 s，写脏为 2.18 s 和 2.42 s。现有页缓存下的重复读取未显示稳定收益，共享恢复缓存与预取继续等待独立证据。
