# M3 local ingress and idle checks

The tests ran on pve-bot with KVM, smolvm 1.37.1, the Debian managed r2 image and the local phase1 runtime socket. Each used a separate temporary platform database.

- HTTP fixture `m_95cfeb1d314c51e7e6e41661c9ff92e8`. A request without valid credentials left the machine paused. Twenty authenticated requests targeted the same paused machine. The test checked the durable wake count in SQLite, dropped the backend connection after a POST increment, checked the response's forwarding evidence, and read the application counter back as one.
- TLS fixture `m_aee37b93eadb8315ec2ed08d9ebbd99e`. OpenSSH connected through sandboxctl's WebSocket proxy using strict host-key checking and executed `id -u` as root. A service-scoped client certificate woke a paused VM and returned 90,112 identical bytes after a TLS half-close. Missing and revoked certificates left the VM paused. SSH reconnected to the same verified host key after another pause. A running guest task held the VM beyond its two-second idle threshold. After cancellation, the idle worker paused it. The fixture resumed and deleted the VM and revoked the test SSH key.
- The Go gateway regression test exercises the backend-drop case independently of KVM.

The integration drivers are `tests/integration/product.py` and `tests/integration/secure_ingress.py`. The latter takes a local test CA, server certificate and key, and a client CSR and key. Use an isolated platform listener, temporary credentials and a dedicated mTLS port range.
