# M3 local ingress and idle checks

The tests ran on pve-bot with KVM, smolvm 1.37.1, the Debian managed r2 image and the local phase1 runtime socket. Each used a separate temporary platform database.

- HTTP fixture `m_95cfeb1d314c51e7e6e41661c9ff92e8`. A request without valid credentials left the machine paused. Twenty authenticated requests targeted the same paused machine. The test checked the durable wake count in SQLite, dropped the backend connection after a POST increment, checked the response's forwarding evidence, and read the application counter back as one.
- TLS fixture `m_aee37b93eadb8315ec2ed08d9ebbd99e`. OpenSSH connected through sandboxctl's WebSocket proxy using strict host-key checking and executed `id -u` as root. A service-scoped client certificate woke a paused VM and returned 90,112 identical bytes after a TLS half-close. Missing and revoked certificates left the VM paused. SSH reconnected to the same verified host key after another pause. A running guest task held the VM beyond its two-second idle threshold. After cancellation, the idle worker paused it. The fixture resumed and deleted the VM and revoked the test SSH key.
- The Go gateway regression test exercises the backend-drop case independently of KVM.

The integration drivers are `tests/integration/product.py` and `tests/integration/secure_ingress.py`. The latter takes a local test CA, server certificate and key, and a client CSR and key. Use an isolated platform listener, temporary credentials and a dedicated mTLS port range.

The dispatch proxy also held a successful native idle-pause reply for `op_1cb6465d2e5daa150a3ef54506325c5c`. An authenticated file-list request arrived during capture. SQLite recorded wake_pending while that request was open. The client disconnected before the response was released. The worker finished Pause and one durable Wake brought the VM back. Later in the same run, Stop with cancel_tasks waited for a terminal Guest cancellation receipt. The fixture completed Delete. A separate uninterrupted end-to-end run covered task output, active fork, isolated child cancellation, clean snapshot `op_35929937e88ab254383433212f0aa559`, independent restore `op_9adf6289f026732d0def62747f649b23`, HTTP wake fan-in and exactly-once application counting on the restored machine. Both logical machines were deleted through the API.

A subsequent local run on `m_0850a6976dffe5e2ebbb1dca8fab4261` let a one-second lease expire. Its state became suspect and continued to block idle. Reading metrics preserved last_user_activity_at. Explicit lease release allowed the subsequent idle capture and wake. Raising the disposable registry's storage floor above available disk caused a fresh Create to finish with DISK_LOW and effect none. The proxy counted zero additional native Create calls.

The default r3 archive with SHA-256 `ad5b45167c999b4af5a845de918aff0f6c14d30544c4cadfd32c8aead95f1c64` passed `workspace.py --interrupt-dispatch` against a separate smolvm 1.37.1 runtime. Fixture `m_f4300dac54eed394b3e3bbf357379404` remained running with a suspect lease, and metrics preserved its user-activity timestamp. Idle operation `op_c7e06121a757e758e9c0c3971ef4c000` completed and ran one wake after its waiting client disconnected. The fixture also completed the pause/resume and cold start controls, task cancellation on Stop, and deletion.
