# M1 local integration

On 2026-11-25 the management API ran on pve-bot with Linux 6.8.0-151-generic, 8 vCPUs, 11959 MiB of RAM and /dev/kvm. The local systemd smolvm-phase1 service used the official smolvm v1.37.1 release at 9d3ab4c82756456565544558ac2ea5412afa84ef. Its Linux x86_64 archive SHA-256 was f8d5d1aaa198c7b9e676fa4365998e22fc9051a2199b208741be5f38fef5e404. The CLI and Guest tests use separate disposable machines.

Run from the repository root with a locally registered test archive and the owner's Unix socket permissions.

```sh
go build -o .build/platformd ./cmd/platformd
python3 tests/integration/workspace.py --image /var/lib/smolvm-phase1-images/debian-task-gate-base.tar
```

The scenario created its own owner, DB and listener and used the actual HTTP API and platform worker. The successful run used the Debian base archive with SHA-256 d3b3c90c4f8b78bf68334eaf8359967b57d404b25b075c81cc0e526f3a7ae0e1. A create with start returned machine m_fd9a147c7f8461428d76a7f6084af16b and operation op_3b371bb962e29e6e900952cd029500be. The client killed platformd, restarted against the same SQLite database, logged in using its existing session, replayed the identical intent and received the same operation. An altered intent with the same key returned 409. The list returned one machine. Its running execution subsequently paused, resumed, stopped, cold-started and deleted via five separate successful operations. Delete checked the original native name for absence. The control epoch remained e95a0adb-3cbe-451b-bffb-486c9eb559fc.

An earlier run returned 409 on Stop immediately after a successful Resume. The v1.37.1 supervisor can still be attaching to the new execution. The adapter now reobserves the complete identity and permits a bounded retry only for the exact native pre-dispatch refusal. Transport uncertainty is returned to the operation owner. A separate registry test reopens the DB before any worker has seen the accepted create and verifies replay, fingerprint mismatch and single-writer exclusion.

This scenario exercises M1 control-plane persistence. It does not exercise the full product UI, every crash window, Guest task survival, snapshot independence or Host reboot. Those need their respective scenario records.
